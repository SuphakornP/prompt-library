# Fellow Skill Compass — Concept and implementation

วันที่: 2026-11-13 (Asia/Bangkok)

สถานะ: พัฒนา feature และ skill ดาวน์โหลด 6 รายการแล้วใน branch `codex/skill-discovery-draft`; ยังไม่ได้ deploy สู่ production ดูผลตรวจล่าสุดใน [QA](qa.md)

เอกสารนี้เก็บเหตุผลของแนวคิดเดิม และอธิบายสิ่งที่พัฒนาแล้ว ชื่อไฟล์คงเดิมเพื่อรักษาลิงก์จากร่างแรก

## แนวคิดที่นำมาทำ

**สัมภาษณ์สั้น ๆ เพื่อค้นหาสไตล์ทำงานกับ AI แล้วแนะนำ skill ที่ดาวน์โหลดไปใช้กับงานของคุณได้**

ยืมความสนุกของการค้นพบตัวเองและชื่อสไตล์แบบ MBTI มาใช้ แต่คำแนะนำยึดงานและข้อมูลที่ผู้ใช้มี ผลอธิบายคำตอบในครั้งนี้ ไม่อ้างว่าเป็นแบบทดสอบ MBTI หรือวัดความสามารถทางวิชาชีพ

เลือก guided interview ทีละคำถามแทนแชตปลายเปิด เพื่อให้คำถามและเหตุผลของผลตรวจได้ ทำงานใน frontend เดิมได้ และไม่ต้องเพิ่ม AI API การทดสอบกับผู้ใช้จริงเพื่อวัดเวลาและประโยชน์ของคำแนะนำยังเป็นงานที่ต้องทำต่อ ไม่ประกาศระยะเวลาตอบเป็นตัวเลขที่ยืนยันแล้ว

แยกสิ่งสามอย่างออกจากกัน:

- **Working style:** ชื่อสำหรับอธิบายความชอบ เช่น Organizer หรือ Analyst
- **Skill:** คำสั่งสำหรับงานเฉพาะที่เรียกใช้ซ้ำได้ มีวิธีทำงาน ขอบเขต และรูปแบบผลลัพธ์
- **Download:** ZIP ที่มีเวอร์ชันและคู่มือติดตั้งแยกตามเครื่องมือ ดาวน์โหลดแล้วต้องนำไปติดตั้งเอง การติดตั้งไม่เพิ่มสิทธิ์เข้าถึงแอปหรือบริการให้อัตโนมัติ

คำชวนบนหน้าจอ: **“Find your style. Take a skill with you.”** เมนูหลักใช้ชื่อ **Find your skills**

## เส้นทางที่พัฒนาแล้ว

| หน้า | พฤติกรรม |
| --- | --- |
| `/discover` | อธิบาย feature และเริ่มหรือทำ survey ต่อ |
| `/discover/1` ถึง `/discover/9` | ถามทีละข้อ มี progress, Back และ Continue; ข้ามไปข้อที่ยังขาดคำตอบก่อนหน้าไม่ได้ |
| `/discover/review` | ทบทวนคำตอบและเพิ่มข้อความงานจริงได้ไม่เกิน 500 ตัวอักษร โดยไม่บังคับ |
| `/discover/N/edit` | แก้คำตอบหนึ่งข้อแล้ว Save & review กลับหน้าทบทวน |
| `/discover/result` | แสดงสไตล์และ skill 3 อันดับแรก พร้อมเปิดดูอีก 3 รายการได้ |
| `/prompts/:slug?from=skills` | เปิด prompt ที่เกี่ยวข้องและกลับผล skill ของ session เดิมได้ |

คำตอบและข้อความงานจริงอยู่ในหน่วยความจำของ tab เท่านั้น การ refresh เปิด tab ใหม่ หรือ Start again เริ่ม survey ใหม่ หากเปิดหน้าผลโดยไม่มีคำตอบครบ ระบบชวนกลับมาเริ่มหรือทำต่อ ไม่แสดงผลที่แต่งขึ้น

ไม่มีบัญชีผู้ใช้ backend หรือการเรียก AI เพื่อคำนวณผล คำตอบไม่อยู่ใน URL, local storage หรือ ZIP และไม่ถูกส่งไปบริการ AI ข้อความงานจริงเป็นเพียง reminder ในหน้าผล ไม่ถูกใช้ให้คะแนนหรือใส่ใน prompt อัตโนมัติ

## บทสัมภาษณ์จริง

UI เป็นภาษาอังกฤษตามเว็บไซต์เดิม มีคำถามหลัก 9 ข้อ และข้อความงานจริงที่ไม่บังคับในหน้าทบทวน

| ข้อ | เนื้อหา | กติกา |
| --- | --- | --- |
| 1 | งานส่วนใหญ่ของคุณ | เลือกได้ 2 กลุ่ม; ไม่ให้คะแนนสไตล์หรือ skill |
| 2 | เป้าหมายที่อยากให้ AI ช่วย | เลือก 1 เป้าหมาย |
| 3 | ปัญหาที่ขัดขวางงานนั้น | เลือก 1 ปัญหา |
| 4 | เมื่อโจทย์ยังไม่ชัด คุณเริ่มอย่างไร | ตัวเลือกแรกและตัวเลือกรองที่ไม่บังคับ |
| 5 | เมื่อมีข้อมูลมาก คุณอยากทำอะไรให้เกิดขึ้นก่อน | ตัวเลือกแรกและตัวเลือกรองที่ไม่บังคับ |
| 6 | ส่วนไหนของงานทีมที่คุณสนุก | ตัวเลือกแรกและตัวเลือกรองที่ไม่บังคับ |
| 7 | ประสบการณ์ใช้ AI | เลือก 1 ระดับที่อธิบายตัวเองได้ |
| 8 | เครื่องมือที่จะนำ skill ไปใช้ | ChatGPT / Codex (OpenAI), Claude, เครื่องมืออื่น หรือยังไม่แน่ใจ; แยกวิธีติดตั้งในคู่มือผลลัพธ์ |
| 9 | ข้อมูลตั้งต้นที่มี | เลือกหลายประเภทได้; “ไม่มี” และ “ไม่แน่ใจ” ใช้ร่วมกับประเภทอื่นไม่ได้ |

ข้อ 4–6 ให้คะแนนตามลำดับที่เลือก การเลือกข้อใหม่เมื่อเต็มสองข้อจะแทนตัวเลือกรอง โดยเก็บตัวเลือกแรกไว้ หน้าจอแสดงและประกาศลำดับให้ assistive technology ด้วย ทุกคำถามมีทางตอบที่ไม่บังคับให้ผู้ใช้แสดงความมั่นใจเกินจริง

## สไตล์และกติกาจับคู่

| สไตล์ | ความชอบที่ใช้เล่าผล |
| --- | --- |
| Explorer | ตั้งคำถามและเชื่อมความรู้ |
| Analyst | เปรียบเทียบหลักฐานและเหตุผล |
| Creator | เปลี่ยนไอเดียเป็นผลงานที่เห็นภาพ |
| Communicator | ช่วยคนเข้าใจและทำงานร่วมกัน |
| Organizer | จัดขั้นตอน เจ้าของงาน และสิ่งที่จะทำต่อ |
| Builder | ทดลองและทำวิธีทำงานให้ใช้ซ้ำได้ |

คะแนนสไตล์มาจากข้อ 4–6 เท่านั้น: ตัวเลือกแรก +2 ตัวเลือกรอง +1 หากตอบแบบให้คะแนนน้อยกว่า 2 ข้อ จะยังไม่ตั้งชื่อสไตล์ หากสองอันดับแรกห่างกันไม่เกิน 1 คะแนนจะแสดงสไตล์คู่ และหากมากกว่า 2 สไตล์เสมอกันอันดับแรกจะแสดงผลแบบผสมหลายสไตล์

การแนะนำ skill เป็นอีกการคำนวณหนึ่ง ใช้เป้าหมาย 45%, ปัญหา 25%, ประสบการณ์ 20%, และความชอบ 10% ส่วนความชอบคิดตามสัดส่วนคะแนนสไตล์นั้น ตัวประกอบที่ไม่ทราบถูกตัดออกและปรับน้ำหนักที่เหลือให้เทียบกันได้ คะแนนใช้เรียงภายใน ไม่แสดงเป็นเปอร์เซ็นต์ความสามารถหรือความแม่นยำ

ก่อนเทียบคะแนน ระบบเรียงประเภทความพร้อมของข้อมูล: มีประเภทข้อมูลตั้งต้นที่ skill ใช้ → ยังไม่ทราบ → ต้องเตรียมเพิ่ม จากนั้นเรียงคะแนนและใช้ editorial order เมื่อต้องตัดสินคะแนนเสมอ ความพร้อมระดับประเภทข้อมูลยังไม่ยืนยันว่าเนื้อหาครบ เช่น มี “notes” ไม่ได้แปลว่ามีบันทึกประชุมที่ต้องการแล้ว จึงแสดงรายการ input จริงให้ตรวจอีกครั้ง ภาพหรือ visual reference อย่างเดียวไม่ผ่านความพร้อมของ skill ที่ต้องใช้เนื้อหาแบบข้อความ

หน้าผลยังเปิดให้ดาวน์โหลดทั้ง 6 รายการ แม้ไม่มีข้อมูลพร้อม โดยแนะนำให้เตรียมข้อมูลหรือใช้ตัวอย่างจำลอง รายการที่ไม่ใกล้เป้าหมายถูกอธิบายว่าเป็นทางสำรวจ ไม่ใช้ชื่อสไตล์ล็อกว่าคนใดต้องใช้ skill กลุ่มใด

## สิ่งที่ดาวน์โหลดได้

มี 6 skill เวอร์ชัน `1.0.0`: Research Evidence Brief, Decision Brief, Presentation Storyline, Meeting Follow-through, Workflow Improvement และ Reusable Workflow Blueprint แต่ละ ZIP มี `SKILL.md`, `references/output-template.md` และ `references/example.md` ภายใต้โฟลเดอร์ชื่อ skill หนึ่งชั้น

แต่ละรายการมีขอบเขตเฉพาะ และคำสั่งที่เขียนสำหรับงานนั้นโดยตรง เช่น Presentation Storyline ให้ storyboard แบบข้อความ ไม่ได้อ้างว่าสร้างไฟล์ PowerPoint ส่วน Reusable Workflow Blueprint ให้ specification ไม่ได้ติดตั้งหรือรัน automation รายละเอียด input/output ต้นฉบับ และวิธีใช้ทุกชุดอยู่ใน [คู่มือดาวน์โหลด skill](skill-downloads.md)

คำแนะนำ 3 อันดับแรกแสดงเหตุผล input/output เวอร์ชัน ปุ่มดาวน์โหลด ขนาดไฟล์ วิธีติดตั้ง sample task รายการไฟล์ และ SHA-256 พร้อมทางเปิด related prompt ซึ่งยังมี prerequisites ของตัวเอง ตัวอย่างเช่น skill ประชุมใช้กับประชุมทั่วไปได้ แต่ prompt ที่เกี่ยวข้องใน catalog เน้นประชุมลูกค้า อีก 3 รายการเปิดสำรวจพร้อมดาวน์โหลดและดู sample task ได้

เครื่องมือที่เลือกเปลี่ยนคู่มือติดตั้ง ไม่เพิ่มคะแนนและไม่ยืนยันสิทธิ์บัญชี:

- **Codex:** แตก ZIP และวาง skill folder ในตำแหน่ง local skills ตามคู่มือ
- **Claude:** ใช้เส้นทางอัปโหลด custom skill เมื่อบัญชีและองค์กรเปิดให้ใช้; import จริงยังไม่ได้ทดสอบ
- **ChatGPT / เครื่องมืออื่น:** ใช้ sample task ในแชตได้ การคัดลอก task หรือแนบ ZIP ไม่เท่ากับติดตั้ง skill

ไม่มีการแจก plugin หรือการติดตั้งอัตโนมัติในรุ่นนี้

## โครงสร้าง implementation

| แหล่ง | หน้าที่ |
| --- | --- |
| `src/components/SkillDiscovery.tsx` | Landing, interview, review, results และคู่มือติดตั้ง |
| `src/data/discovery.ts` | คำถามและสไตล์ |
| `src/data/skills.json` | Metadata, sample tasks, mapping และ input categories |
| `src/lib/skill-discovery.ts` | ตรวจคำตอบ คำนวณสไตล์ readiness และอันดับ skill |
| `content/skills/<id>/` | คำสั่ง template และตัวอย่างฉบับต้นทาง |
| `scripts/build-skills.mjs` | ตรวจต้นฉบับและสร้าง distribution ที่ทำซ้ำได้ |
| `src/data/skill-downloads.json` | Manifest ที่มีเวอร์ชัน URL ขนาดไฟล์ และ SHA-256 |
| `public/downloads/skills/` | ZIP ที่สร้างระหว่าง build และไม่เก็บใน Git |

`npm run build:skills` ทำงานก่อน `dev`, `test` และ `build` ผ่าน npm lifecycle hooks หากแก้ source skill ขณะ dev server เปิดอยู่ ให้รันคำสั่งนี้อีกครั้ง รายการ prompt เดิมและ generated catalog ไม่ถูกใช้แทนเนื้อหา skill หรือแก้ด้วยมือ

## สิ่งที่เปลี่ยนจากร่างแรกโดยตั้งใจ

- Download เป็นส่วนหลักของรุ่นนี้ มีไฟล์จริง 6 ชุด แทนการแนะนำเพียง prompt bundle หรือมี sample ZIP ชุดเดียว
- ใช้ 9 คำถามคงที่และ optional task ใน review ไม่มีคำถามติดตามอัตโนมัติสูงสุด 2 ข้อตามแนวคิดช่วงแรก
- แยก material readiness ออกจากวิธีติดตั้ง แพลตฟอร์มไม่ใช่คะแนนความเหมาะสม และไม่มีการตรวจสิทธิ์บัญชีผู้ใช้จากเว็บไซต์
- แสดงคำแนะนำ 3 รายการพร้อมสถานะเตรียมข้อมูล และเปิดดูอีก 3 ได้ แทนการซ่อนสิ่งที่ยังไม่พร้อมทั้งหมด
- ไม่รวม AI interview, personalized ZIP, share card, analytics, team dashboard หรือ plugin distribution เป็น feature ที่เสร็จแล้ว

## หลักฐานและข้อจำกัด

ผ่านการตรวจโครงสร้างทั้ง 6 skill และมี instruction-guided trial ด้วยงานจำลองอย่างละหนึ่งงาน ผลเหล่านี้ไม่ใช่การวัดความแม่นยำหรือความเสถียรจากการรันซ้ำทุกแพลตฟอร์ม

Native Codex ในโปรเจกต์ชั่วคราวค้นพบทั้ง 6 skill และเรียก Meeting Follow-through โดยระบุชื่อได้สำเร็จกับงานภาษาไทย โดยไม่แก้ไฟล์ skill ที่ผู้ใช้ติดตั้งไว้ การเรียกแบบ native ของอีก 5 skill, automatic triggering และ Claude import/invocation ยังไม่ได้ตรวจ

ผล browser QA, checks และข้อจำกัดของ behavioral trials บันทึกใน [QA](qa.md) ยังไม่มี deployment สู่ production และยังไม่มีการทดลอง survey กับผู้ใช้จริงเพื่อยืนยันคุณภาพการจับคู่
